# Lossless PNG feasibility

## Execution prompt

Continue the ordered backlog from updated develop with one bounded research task:
benchmark browser-local PNG encoders before implementing Lossless PNG Optimizer.
Read AGENTS.md and the development, communication, SDLC and applicable engineering
skills. Inspect the existing PNG compressor and upstream issues359/295/PR461.
Compare the installed palette compressor at maximum quality, native canvas PNG
and native IDAT recompression without decoding/re-encoding samples. Use generated
fixtures, including gradients with more than4096 colors, alpha/hidden RGB,
metadata,16-bit, indexed and interlaced PNG. Independently check decoded pixels,
raw filtered samples, dimensions, non-IDAT metadata and non-inflation selection.
Record reproducible per-browser bytes/timings, limits, dependency/license tradeoffs
and an explicit proceed/defer decision. Do not add a runtime feature, WASM/package,
upload, persistence or production deployment. Keep experimental code outside src.
Review and validate, deliver one PR into develop with exact-head required CI and
verified cleanup. Do not start implementation of the next slice automatically.

## Question and scope

Can the current dependency or a dependency-free browser encoder meet a strictly
lossless sample/metadata contract, and is the saving useful enough to justify a
separate worker/UI implementation? This spike measures synthetic fixtures, not
representative customer compression ratios or a shipped optimizer.

The harness runs only locally, uses generated bytes and serves the installed
browser-image-compression2.0.2 bundle over loopback. No upstream code is copied.
The native-stream candidate only recompresses existing filtered scanlines; it does
not choose better filters, palettes or color types. The Node harness assembles
trusted fixtures and validates output with node:zlib and installed Jimp. It is
not an admission parser for untrusted files. Native canvas/Jimp comparisons are
8-bit RGBA observations; exact inflated-byte comparison additionally detects
16-bit precision/hidden-sample changes in the stream candidate.

## Reproduce

Install the lockfile dependencies and Playwright browsers, then run:

```sh
node scripts/research/png-feasibility.mjs --output /workspace/work/png-feasibility/results.json
```

Three sequential samples per candidate/fixture/browser; first result is included
(no discarded warmup). Timing is informational and has no pass/fail threshold.
Fixture generation and Node output assembly/validation are excluded. Timings
include IPC serialization/transfer and result collection. Library/canvas include
browser decode/encode; stream timings
include worker startup, decompression/compression and worker message transfer, but
not Node PNG assembly. These are different operations, not a normalized speed race.
No memory measurement or hard native allocation quota is inferred from byte caps.
Each browser operation has a15-second parent deadline; a failure closes its browser
in finally. The stream worker additionally has a10-second termination deadline.
Library/canvas main-thread work has no synchronous preemption guarantee.
